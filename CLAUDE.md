# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

CloudShare – Outlook add-in for classic and new Outlook on Exchange Online: large files are uploaded to the sender's own Nextcloud account and inserted as a password-protected public link; the password is delivered to the same recipients in a second, automatically sent mail as a Vaultwarden Send. Full architecture, setup (Entra ID, Nextcloud user_oidc, Vaultwarden) and known risks: `docs/architecture.md`; operations manual: `README.md`. Conventions: everything in the repository is English – identifiers, code comments, file names, documentation, logs and admin-facing script output. Only text seen by end users and mail recipients stays German: taskpane UI, Outlook notifications/Smart Alert texts, manifest labels, the password mail and `HttpError` messages shown in the add-in.

## Commands

No local Node/Docker on the dev machine at time of writing; everything builds in Docker.

- Deployment: self-contained hardened stack (see `README.md`). Repo cloned to `/opt/cloudshare`; `./setup.sh` is an interactive wizard writing `env/` (700): `versions.env` (Compose variables from `versions.env.example`: `CLOUDSHARE_HOST`, `CLOUDSHARE_VERSION`, `CADDY_VERSION`) and `cloudshare.env` (all app settings + secrets, values quoted for Compose; `cloudshare.env.example` is only a reference). `compose.yml` runs its own Caddy (`cloudshare-caddy`, ports 80/443, Let's Encrypt, `caddy/Caddyfile` with `{$CLOUDSHARE_HOST}`) in front of `cloudshare`; the site must not set `X-Frame-Options` (Outlook embeds the taskpane). Networks: `internal` (Caddy ↔ CloudShare, `internal: true`), `edge` (Caddy), `egress` (CloudShare → Entra/Graph, Nextcloud, Vaultwarden via their public URLs). No internal IPs or host-specific values in the public repository. The image is never built on the server: `.github/workflows/image.yml` builds `ghcr.io/mrprohl/cloudshare` (tags `latest`, `sha-<commit>`, semver from `v*` tags; linux/amd64) on pushes to `main` touching `addin/`, `server/`, `docker/` or `Dockerfile` – only in the public repository (jobs are skipped when the repository is private); the server updates by re-pulling. The Bitwarden CLI version is the `BW_CLI_VERSION` build arg default in the `Dockerfile` (installed in its own stage with npm `overrides` for vulnerable transitive dependencies; npm is removed from the runtime image). `docker-compose.yml` is the Portainer/Dockhand stub that `include`s `compose.yml` (absolute `/opt/cloudshare` paths). Read-only, `cap_drop: ALL` (Caddy: `NET_BIND_SERVICE`), only Caddy publishes ports. Keep this structure; `env/` is gitignored. Documentation uses `cloudshare.example.com`, `cloud.example.com`, `vault.example.com` – never real host names, IPs or personal data.
- Backend (`server/`): `npm install`, `npm run build`, `npm run typecheck`
- Add-in (`addin/`): `npm install`, `npm run build` (esbuild → `addin/dist`), `npm run typecheck`
- Tests (vitest): `npm test` in `server/` and `addin/`; `npm run validate:manifest` in `addin/`. The server is split into `src/app.ts` (`buildApp()`, all routes, used by `test/api.test.ts` via `fastify.inject`, which mocks `auth.js`, `vaultwarden.js` and `NextcloudClient`) and `src/index.ts` (start, vault unlock, job watcher). Add-in event handlers are tested with an Office.js mock (`addin/test/officeMock.ts`).; tests live in `*/test/` (server tests get a dummy config and temp `DATA_DIR` from `server/test/setup.ts`, network calls are mocked via `mockFetch` in `server/test/helpers.ts`; `jobs.test.ts` mocks `graph.js`). The GitHub workflow runs type check, tests, `npm audit --omit=dev`, manifest validation, ShellCheck and `ci/stack.sh validate` (setup.sh with dummy answers, compose config, caddy validate), then builds the image, scans it with Trivy (critical/high, fixed), runs `ci/stack.sh smoke` (real stack with Caddy on the runner, Bitwarden CLI mocked via `ci/fake-bw` + `ci/compose.smoke.yml`) and only then pushes. Pull requests run all checks but never push. Deployment is manual (no CD). Security: Dependabot (`.github/dependabot.yml`, alerts + security updates), CodeQL default setup (extended), secret scanning + push protection – all configured on the public repository. No linter.

## Architecture

One container serves everything behind Caddy:
- `server/` – Fastify backend (ESM, TypeScript). Validates the Office SSO token (`auth.ts`, audience `api://<host>/<client-id>`, scope `access_as_user`) and uses MSAL On-Behalf-Of only for Graph (`Mail.Send`).
- Nextcloud does not accept Entra tokens (typically it logs in via another IdP, e.g. Keycloak through `user_oidc`). Instead each user connects once via Nextcloud Login Flow v2; the resulting app password is stored AES-256-GCM-encrypted per Entra `oid` in `/data` (`credentials.ts`, key `CREDENTIAL_KEY`) and used as Basic auth. A 401 from Nextcloud deletes the stored credential and returns error code `NEXTCLOUD_NOT_CONNECTED`, which makes the taskpane show the connect view.
- Nextcloud access is server-to-server (no CORS on Nextcloud): WebDAV chunked upload v2 + OCS share API (`nextcloud.ts`). Nextcloud-reported URLs are rewritten onto `NEXTCLOUD_URL`. Vaultwarden Sends are created through `bw serve` running in the same container on 127.0.0.1:8087 with a service account (`vaultwarden.ts`). Upload/job/pending-login state is in-memory (`store.ts`) → single instance only.
- `addin/` – XML manifest + taskpane (Nextcloud connect/disconnect, converts existing attachments via `getAttachmentContentAsync` → upload → `removeAttachmentAsync`, plus file picker for files beyond Outlook's limit; inserts links) + event handlers in `commands.ts`: `OnMessageAttachmentsChanged` shows an InsightMessage with a "open taskpane" action (add-ins cannot open the taskpane themselves), `OnMessageSend` runs with manifest `SendMode="SoftBlock"`; env `ATTACHMENT_POLICY` (served via `/api/config`, cached in `roamingSettings`) decides: `enforce` blocks large attachments before arming the password mail (no "Send anyway", opt-out checkbox hidden), `suggest` arms the password mail first and relaxes to PromptUser via `sendModeOverride` (Mailbox 1.14). The taskpane mimics Outlook (Fluent 2 tokens, Office theme, Outlook wording "Nachricht"/"Kennwort") – keep new UI consistent with that. Bundled as IIFE because classic Outlook runs the handlers in a JavaScript-only runtime (no DOM, no ES modules).
- Taskpane has two tabs: "Senden" (attachments, password, upload link "Dateien anfordern" via `/api/requests`) and "Meine Freigaben" (`/api/shares`, revoke via `DELETE /api/shares/:id`). Links are inserted as an email-safe HTML card (`addin/src/taskpane/mailCard.ts`, tables + inline styles, optional `MAIL_FOOTER` template filled from the sender's profile via `/api/profile`, see `footer.ts`).
- Per-draft state lives in `item.sessionData` (`DraftState` in `shared/office.ts`: `jobId`, `password`, `optOut`). All files of one mail share one password, one Vaultwarden Send and one password mail; the backend appends to an existing job via `jobId` on `/complete` unless it was already dispatched. The password mail is sent only after the mail was really sent: the taskpane tags the draft with the Office.js custom property `cloudshareJob` (MAPI `cecp-<add-in ID>`, `ADDIN_ID` env must match the manifest `<Id>`), the send handler only arms the job (`/api/jobs/:id/arm`, stores a Graph token with Mail.Read(.Shared) + Mail.Send(.Shared); the handler passes a "From" that differs from the user so shared-mailbox "Sent Items" are searched too and the password mail uses the same sender), and `server/src/jobs.ts` polls "Sent Items" and then mails the actual recipients. Jobs persist encrypted in `/data/password-jobs.json` (`storage.ts` holds the shared AES-GCM + atomic-write helpers). No upload size cap except the user's Nextcloud quota (checked up front via OCS `cloud/user`, 507 → `NEXTCLOUD_QUOTA_EXCEEDED`).
- Placeholders `%%PUBLIC_BASE_URL%%`, `%%PUBLIC_HOST%%`, `%%ENTRA_CLIENT_ID%%` in add-in files and manifest are replaced by `docker/entrypoint.sh` at container start (copied from `/app/public.tpl` to `/app/public`), so one image works for any environment. The backend also serves `/manifest.xml` for the M365 admin center.
- Keep `docker/entrypoint.sh` LF-only (enforced by `.gitattributes`).
