# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

CloudShare – Outlook add-in for classic and new Outlook on Exchange Online: large files are uploaded to the sender's own Nextcloud account and inserted as a password-protected public link; the password is delivered to the same recipients in a second, automatically sent mail as a Vaultwarden Send. Full architecture, setup (Nextcloud user_oidc, Vaultwarden) and known risks: `docs/architecture.md`; Microsoft 365 step by step (Entra app registration, add-in deployment, Exchange, error table): `docs/microsoft-365.md`; operations manual: `README.md`. Conventions: everything in the repository is English – identifiers, code comments, file names, documentation, logs and admin-facing script output. Text seen by end users and mail recipients (taskpane UI, Outlook notifications/Smart Alert texts, manifest labels, link cards, password mail, SMS/templates defaults, `HttpError` messages shown in the add-in) is never written inline: it lives in the language files `locales/<language>.json` (`de` default, `en`; env `LANGUAGE`) – add-in code uses `t("key")` from `addin/src/shared/i18n.ts` (section `addin`), the server `t("section.key")` from `server/src/i18n.ts`, `taskpane.html`/`manifest.xml` use `%%t:section.key%%`. Every new key goes into every language file with the same placeholders (`server/test/i18n.test.ts` enforces it, plural forms `_one`/`_other`). Keep the German wording Outlook-like ("Nachricht", "Kennwort").

## Commands

No local Node/Docker on the dev machine at time of writing; everything builds in Docker.

- Deployment: self-contained hardened stack (see `README.md`). Repo cloned to `/opt/cloudshare`; `./setup.sh` is an interactive wizard writing `env/` (700): `versions.env` (Compose variables from `versions.env.example`: `CLOUDSHARE_HOST`, `CLOUDSHARE_VERSION`, `CADDY_VERSION`) and `cloudshare.env` (all app settings + secrets, values quoted for Compose; `cloudshare.env.example` is only a reference). `compose.yml` runs its own Caddy (`cloudshare-caddy`, ports 80/443, Let's Encrypt, `caddy/Caddyfile` with `{$CLOUDSHARE_HOST}`) in front of `cloudshare`; the site must not set `X-Frame-Options` (Outlook embeds the taskpane). Networks: `internal` (Caddy ↔ CloudShare, `internal: true`), `edge` (Caddy), `egress` (CloudShare → Entra/Graph, Nextcloud, Vaultwarden via their public URLs). No internal IPs or host-specific values in the public repository. The image is never built on the server: `.github/workflows/image.yml` builds `ghcr.io/mrprohl/cloudshare` (tags `latest`, `sha-<commit>`, semver from `v*` tags; linux/amd64) on pushes to `main` touching `addin/`, `server/`, `docker/` or `Dockerfile` – only in the public repository (jobs are skipped when the repository is private); the server updates by re-pulling. The Bitwarden CLI version is the `BW_CLI_VERSION` build arg default in the `Dockerfile` (installed in its own stage with npm `overrides` for vulnerable transitive dependencies; npm is removed from the runtime image). `docker-compose.yml` is the Portainer/Dockhand stub that `include`s `compose.yml` (absolute `/opt/cloudshare` paths). Read-only, `cap_drop: ALL` (Caddy: `NET_BIND_SERVICE`), only Caddy publishes ports. Keep this structure; `env/` is gitignored. Documentation uses `cloudshare.example.com`, `cloud.example.com`, `vault.example.com` – never real host names, IPs or personal data.
- Backend (`server/`): `npm install`, `npm run build`, `npm run typecheck`
- Add-in (`addin/`): `npm install`, `npm run build` (esbuild → `addin/dist`), `npm run typecheck`
- Tests (vitest): `npm test` in `server/` and `addin/`; `npm run validate:manifest` in `addin/`. The server is split into `src/app.ts` (`buildApp()`, all routes, used by `test/api.test.ts` via `fastify.inject`, which mocks `auth.js`, `vaultwarden.js` and `NextcloudClient`) and `src/index.ts` (start, vault unlock, job watcher). Add-in event handlers are tested with an Office.js mock (`addin/test/officeMock.ts`).; tests live in `*/test/` (server tests get a dummy config and temp `DATA_DIR` from `server/test/setup.ts`, network calls are mocked via `mockFetch` in `server/test/helpers.ts`; `jobs.test.ts` mocks `graph.js`). The GitHub workflow runs type check, tests, `npm audit --omit=dev`, manifest validation, ShellCheck and `ci/stack.sh validate` (setup.sh with dummy answers, compose config, caddy validate), then builds the image, scans it with Trivy (critical/high, fixed), runs `ci/stack.sh smoke` (real stack with Caddy on the runner, Bitwarden CLI mocked via `ci/fake-bw` + `ci/compose.smoke.yml`), `ci/stack.sh upgrade` (data written by the published `latest` via `ci/upgrade/seed.mjs` must be readable by the new image, `verify.mjs`) and `ci/stack.sh load` (k6 `ci/load/upload.js` against the stack with `ci/compose.load.yml`: `ci/mocks/server.mjs` mocks Nextcloud and the Entra signing keys via `ENTRA_JWKS_URL` – test-only, never set in production) and only then pushes. A parallel `ui` job runs Playwright UI tests of the built taskpane (`addin/e2e`, `npm run test:ui`: Office.js mock `office-mock.js`, API route mocks, axe accessibility, screenshots as artifact). Pull requests run all checks but never push. Deployment is manual (no CD). Security: Dependabot (`.github/dependabot.yml`, alerts + security updates), CodeQL default setup (extended), secret scanning + push protection – all configured on the public repository. No linter.

## Architecture

One container serves everything behind Caddy:
- `server/` – Fastify backend (ESM, TypeScript). Validates the Office SSO token (`auth.ts`, audience `api://<host>/<client-id>`, scope `access_as_user`) and uses MSAL On-Behalf-Of only for Graph (`Mail.Send`).
- Nextcloud does not accept Entra tokens (typically it logs in via another IdP, e.g. Keycloak through `user_oidc`). Instead each user connects once via Nextcloud Login Flow v2; the resulting app password is stored AES-256-GCM-encrypted per Entra `oid` in `/data` (`credentials.ts`, key `CREDENTIAL_KEY`) and used as Basic auth. A 401 from Nextcloud deletes the stored credential and returns error code `NEXTCLOUD_NOT_CONNECTED`, which makes the taskpane show the connect view.
- Nextcloud access is server-to-server (no CORS on Nextcloud): WebDAV chunked upload v2 + OCS share API (`nextcloud.ts`). Nextcloud-reported URLs are rewritten onto `NEXTCLOUD_URL`. Vaultwarden Sends are created through `bw serve` running in the same container on 127.0.0.1:8087 with a service account (`vaultwarden.ts`). Upload/job/pending-login state is in-memory (`store.ts`) → single instance only.
- `addin/` – XML manifest + taskpane (Nextcloud connect/disconnect, converts existing attachments via `getAttachmentContentAsync` → upload → `removeAttachmentAsync`, plus file picker (`window.showOpenFilePicker` first, hidden `<input type="file">` as fallback – classic Outlook's WebView did not reliably open the dialog for a file input; steps are traced with `CLIENT_TRACE`) and drag & drop onto the "Senden" tab for files beyond Outlook's limit – in classic Outlook the WebView2 file dialog sometimes opens behind the Outlook window; inserts links) + event handlers in `commands.ts`: `OnMessageAttachmentsChanged` shows an InsightMessage with a "open taskpane" action (add-ins cannot open the taskpane themselves), `OnMessageSend` runs with manifest `SendMode="SoftBlock"`; env `ATTACHMENT_POLICY` (served via `/api/config`, cached in `roamingSettings`) decides: `enforce` blocks large attachments before arming the password mail (no "Send anyway"), `suggest` arms the password mail first and relaxes to PromptUser via `sendModeOverride` (Mailbox 1.14). The taskpane mimics Outlook (Fluent 2 tokens, Office theme, Outlook wording "Nachricht"/"Kennwort") – keep new UI consistent with that. Bundled as IIFE because classic Outlook runs the handlers in a JavaScript-only runtime (no DOM, no ES modules); `commands.js` is built with target `es2016` and without `Headers`/`Promise.finally` (guarded by `addin/test/bundle.test.ts`); it registers its handlers immediately (classic) and again in `Office.onReady` (browser runtime: office.js loads `Office.actions` only after the script ran – `commands-load.test.ts`), and that runtime only allows SSO and fetch because the server serves `/.well-known/microsoft-officeaddins-allowed.json` listing `commands.js`.
- Taskpane has two tabs: "Senden" and "Meine Freigaben" (`/api/shares`, revoke via `DELETE /api/shares/:id`). "Senden" starts with a switch (`kind` radios, `selectKind`/`renderKind` in `taskpane.ts`) between "Dateien" (attachments + drop zone), "Vertraulich" (confidential text via `/api/messages` = a Vaultwarden text Send protected with the step password, never stored in Nextcloud) and "Anfordern" (upload link via `/api/requests`); only the chosen part is shown and the single footer button `#submit` names what it inserts (`renderSubmit`). Below: password, "Kennwort senden an" (`<select>`), and "Gültigkeit" collapsed behind a one-line summary (`renderValidity`). "Ohne Kennwort" is only offered for "Dateien" – prevent invalid choices in the UI rather than reporting them after the click. Links are inserted as an email-safe HTML card (`addin/src/taskpane/mailCard.ts`, tables + inline styles, optional `MAIL_FOOTER` template filled from the sender's profile via `/api/profile`, see `footer.ts`).
- Per-draft state lives in `item.sessionData` (`DraftState` in `shared/office.ts`: `jobId`, `password`, `noPassword`, `maxAccess`, `passwordTo` = other password recipient (job field, only that address gets the password mail), `separate` = one password and password mail per "Als Link einfügen" step (`step` ID per click, `PasswordJob.separate`), `links` = share tokens of inserted links; if none of them is left in the body, `releaseDraftIfLinksGone` drops job/password/tag – taskpane on focus and every 4 s while locked, send handler before arming; drafts without `links` are never released). All files of one mail share one password, one Vaultwarden Send and one password mail (or, with "Ohne Kennwort" – file links only, `noPassword: true` on `/complete` – no password, no Send; with `DOWNLOAD_NOTICE` a job without password (`PasswordJob.noPassword`, `noticeShares`) only waits for the sent mail to register the download confirmation; `DraftState.noPassword` + `jobId`). With "per SMS" the pane hides "Kennwort abrufbar"/"Kennwort-Link gültig für" and SMS steps get Sends with `SEND_MAX_EXPIRE_DAYS`; the backend appends to an existing job via `jobId` on `/complete` unless it was already dispatched. The password mail is sent only after the mail was really sent: the taskpane tags the draft with the Office.js custom property `cloudshareJob` (MAPI `cecp-<add-in ID>`, `ADDIN_ID` env must match the manifest `<Id>`), the send handler only arms the job (`/api/jobs/:id/arm`, stores a Graph token with Mail.Read(.Shared) + Mail.Send(.Shared); the handler passes a "From" that differs from the user so shared-mailbox "Sent Items" are searched too and the password mail uses the same sender), and `server/src/jobs.ts` polls "Sent Items" and then mails the actual recipients. Password channel per mail: recipients, `passwordTo` or `passwordSms` (seven.io, `sms.ts`, after sending, password read from the Send, webhook `/webhooks/seven`, status in `deliveries.ts`); optional `templates.json` (`templates.ts`, user → department → default) and download confirmation (`notices.ts`, app permission `Mail.Send`). Jobs persist encrypted in `/data/password-jobs.json`, the cleanup list of uploaded files (`cleanup.ts`, `CLEANUP_AFTER_DAYS`, deletes upload folders after link expiry) in `/data/cleanup.json` (`storage.ts` holds the shared AES-GCM + atomic-write helpers). No upload size cap except the user's Nextcloud quota (checked up front via OCS `cloud/user`, 507 → `NEXTCLOUD_QUOTA_EXCEEDED`).
- Placeholders `%%PUBLIC_BASE_URL%%`, `%%PUBLIC_HOST%%`, `%%ENTRA_CLIENT_ID%%` in add-in files and manifest are replaced by `docker/entrypoint.sh` at container start (copied from `/app/public.tpl` to `/app/public`), so one image works for any environment. Then `server/src/index.ts` runs `localizePublic` (`i18n.ts`): the string marker `"%%CLOUDSHARE_I18N%%"` in the JS bundles becomes the `addin` texts as JSON, `%%t:…%%`/`%%LANG%%`/`%%LOCALE%%` in HTML and manifest the texts of `LANGUAGE` (English as fallback, own files/overrides from `/config/locales`, mounted from `env/config/` together with `templates.json`). Comments in these files must not contain `%%` (the smoke test fails on leftovers). UI tests and manifest validation localize via `addin/scripts/localize.mjs`; add-in unit tests load `locales/de.json` in `addin/test/setup.ts`. The backend also serves `/manifest.xml` for the M365 admin center.
- Keep `docker/entrypoint.sh` LF-only (enforced by `.gitattributes`).
