# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

CloudShare – Outlook add-in for classic and new Outlook on Exchange Online: large files are uploaded to the sender's own Nextcloud account and inserted as a password-protected public link; the password is delivered to the same recipients in a second, automatically sent mail as a Vaultwarden Send. Full architecture, setup (Nextcloud user_oidc, Vaultwarden) and known risks: `docs/architecture.md`; Microsoft 365 step by step (Entra app registration, add-in deployment, Exchange, error table): `docs/microsoft-365.md`; operations manual: `README.md`. Conventions: everything in the repository is English – identifiers, code comments, file names, documentation, logs and admin-facing script output. Text seen by end users and mail recipients (taskpane UI, Outlook notifications/Smart Alert texts, manifest labels, link cards, password mail, SMS/templates defaults, `HttpError` messages shown in the add-in) is never written inline: it lives in the language files `locales/<language>.json` (`de`, `en`): the add-in follows the Outlook display language (`Office.context.displayLanguage`, English if there is no file – `pickLanguage`), sends it as header `X-CloudShare-Language` so `server.*` error texts come in it (`AsyncLocalStorage`, `withRequestLanguage`), what recipients get – link card, password mail, SMS – comes in the language chosen per mail under "Sprache für die Empfänger" (`#recipient-language` in "Gültigkeit und Sprache", preselected by the personal setting `recipientLanguage`; card via `inLanguage`, server per step `SeparatePart.language` + `inRecipientLanguage`), while notes to the sender (download/upload confirmation, SMS notes) come in the language of their add-in when they pressed "Send" (`ArmedSend.language` → `Notice.language`, `PasswordRef.senderLanguage`, `inSenderLanguage`), `templates.json` may hold texts per language per level (`"languages"`, `mailLanguage`), the manifest gets Overrides for each language's `_meta.locale` and `_meta.regions` (`manifestLocales`), and env `LANGUAGE` (default `en`) is the preselection and fallback – add-in code uses `t("key")` from `addin/src/shared/i18n.ts` (section `addin`), the server `t("section.key")` from `server/src/i18n.ts`, `taskpane.html`/`manifest.xml` use `%%t:section.key%%`. Every new key goes into every language file with the same placeholders (`server/test/i18n.test.ts` enforces it, plural forms `_one`/`_other`). Keep the German wording Outlook-like ("Nachricht", "Kennwort").

## Commands

No local Node/Docker on the dev machine at time of writing; everything builds in Docker.

- Deployment: self-contained hardened stack (see `README.md`). Repo cloned to `/opt/cloudshare`; `./setup.sh` is an interactive wizard writing `env/` (700): `versions.env` (Compose variables from `versions.env.example`: `CLOUDSHARE_HOST`, `CLOUDSHARE_VERSION`, `CADDY_VERSION`) and `cloudshare.env` (all app settings + secrets, values quoted for Compose; `cloudshare.env.example` is only a reference). `compose.yml` runs its own Caddy (`cloudshare-caddy`, ports 80/443, Let's Encrypt, `caddy/Caddyfile` with `{$CLOUDSHARE_HOST}`) in front of `cloudshare`; the site must not set `X-Frame-Options` (Outlook embeds the taskpane). Networks: `internal` (Caddy ↔ CloudShare, `internal: true`), `edge` (Caddy), `egress` (CloudShare → Entra/Graph, Nextcloud, Vaultwarden via their public URLs). No internal IPs or host-specific values in the public repository. The image is never built on the server: `.github/workflows/image.yml` builds `ghcr.io/mrprohl/cloudshare` (tags `latest`, `sha-<commit>`, semver from `v*` tags; linux/amd64) on pushes to `main` touching `addin/`, `server/`, `docker/` or `Dockerfile` – only in the public repository (jobs are skipped when the repository is private); the server updates by re-pulling. The Bitwarden CLI version is the `BW_CLI_VERSION` build arg default in the `Dockerfile` (installed in its own stage with npm `overrides` for vulnerable transitive dependencies; npm is removed from the runtime image). `docker-compose.yml` is the Portainer/Dockhand stub that `include`s `compose.yml` (absolute `/opt/cloudshare` paths). Read-only, `cap_drop: ALL` (Caddy: `NET_BIND_SERVICE`), only Caddy publishes ports. Keep this structure; `env/` is gitignored. Documentation uses `cloudshare.example.com`, `cloud.example.com`, `vault.example.com` – never real host names, IPs or personal data.
- Backend (`server/`): `npm install`, `npm run build`, `npm run typecheck`
- Add-in (`addin/`): `npm install`, `npm run build` (esbuild → `addin/dist`), `npm run typecheck`
- Tests (vitest): `npm test` in `server/` and `addin/`; `npm run validate:manifest` in `addin/`. The server is split into `src/app.ts` (`buildApp()`, all routes, used by `test/api.test.ts` via `fastify.inject`, which mocks `auth.js`, `vaultwarden.js` and `NextcloudClient`) and `src/index.ts` (start, vault unlock, job watcher). Add-in event handlers are tested with an Office.js mock (`addin/test/officeMock.ts`).; tests live in `*/test/` (server tests get a dummy config and temp `DATA_DIR` from `server/test/setup.ts`, network calls are mocked via `mockFetch` in `server/test/helpers.ts`; `jobs.test.ts` mocks `graph.js`). The GitHub workflow runs type check, tests, `npm audit --omit=dev`, manifest validation, ShellCheck and `ci/stack.sh validate` (setup.sh with dummy answers, compose config, caddy validate), then builds the image, scans it with Trivy (critical/high, fixed), runs `ci/stack.sh smoke` (real stack with Caddy on the runner, Bitwarden CLI mocked via `ci/fake-bw` + `ci/compose.smoke.yml`), `ci/stack.sh upgrade` (data written by the published `latest` via `ci/upgrade/seed.mjs` must be readable by the new image, `verify.mjs`) and `ci/stack.sh load` (k6 `ci/load/upload.js` against the stack with `ci/compose.load.yml`: `ci/mocks/server.mjs` mocks Nextcloud and the Entra signing keys via `ENTRA_JWKS_URL` – test-only, never set in production) and only then pushes. Pull requests run all checks but never push. Deployment is manual (no CD). Security: Dependabot (`.github/dependabot.yml`, alerts + security updates), CodeQL default setup (extended), secret scanning + push protection – all configured on the public repository. No linter.

## Architecture

One container serves everything behind Caddy:
- `server/` – Fastify backend (ESM, TypeScript). Validates the Office SSO token (`auth.ts`, audience `api://<host>/<client-id>`, scope `access_as_user`) and uses MSAL On-Behalf-Of only for Graph (`Mail.Send`).
- Nextcloud does not accept Entra tokens (typically it logs in via another IdP, e.g. Keycloak through `user_oidc`). Instead each user connects once via Nextcloud Login Flow v2; the resulting app password is stored encrypted per Entra `oid` in the database (`credentials.ts`, store `credentials`, key `CREDENTIAL_KEY`) and used as Basic auth. A 401 from Nextcloud deletes the stored credential and returns error code `NEXTCLOUD_NOT_CONNECTED`, which makes the taskpane show the connect view.
- Nextcloud access is server-to-server (no CORS on Nextcloud): WebDAV chunked upload v2 + OCS share API (`nextcloud.ts`). Nextcloud-reported URLs are rewritten onto `NEXTCLOUD_URL`. Vaultwarden Sends are created through `bw serve` running in the same container on 127.0.0.1:8087 with a service account (`vaultwarden.ts`). Upload/job/pending-login state is in-memory (`store.ts`) → single instance only.
- `addin/` – XML manifest + taskpane (Nextcloud connect/disconnect, converts existing attachments via `getAttachmentContentAsync` → upload → `removeAttachmentAsync`, plus file picker (`window.showOpenFilePicker` first, hidden `<input type="file">` as fallback – classic Outlook's WebView did not reliably open the dialog for a file input; steps are traced with `CLIENT_TRACE`) and drag & drop onto the "Senden" tab for files beyond Outlook's limit – in classic Outlook the WebView2 file dialog sometimes opens behind the Outlook window; inserts links) + event handlers in `commands.ts`: `OnMessageAttachmentsChanged` shows an InsightMessage with a "open taskpane" action (add-ins cannot open the taskpane themselves), `OnMessageSend` runs with manifest `SendMode="SoftBlock"`; env `ATTACHMENT_POLICY` (served via `/api/config`, cached in `roamingSettings`) decides: `enforce` blocks large attachments before arming the password mail (no "Send anyway"), `suggest` arms the password mail first and relaxes to PromptUser via `sendModeOverride` (Mailbox 1.14). The taskpane mimics Outlook (Fluent 2 tokens, Office theme, Outlook wording "Nachricht"/"Kennwort") – keep new UI consistent with that. Messages run down (`SUCCESS_MESSAGE_SECONDS`, default 5: a ring around the tick, "!" or "i" empties clockwise, paused on hover/focus, `setStatus`); progress (kind `progress`) and messages with "Erneut versuchen" stay. Bundled as IIFE because classic Outlook runs the handlers in a JavaScript-only runtime (no DOM, no ES modules); `commands.js` is built with target `es2016` and without `Headers`/`Promise.finally` (guarded by `addin/test/bundle.test.ts`); it registers its handlers immediately (classic) and again in `Office.onReady` (browser runtime: office.js loads `Office.actions` only after the script ran – `commands-load.test.ts`), and that runtime only allows SSO and fetch because the server serves `/.well-known/microsoft-officeaddins-allowed.json` listing `commands.js`.
- Taskpane has two tabs: "Senden" and "Verlauf" (`/api/shares`: all valid links, loaded with the tab, on focus and by `#refresh-shares` in the tab bar (only on the link tabs); one quiet bottom bar `.account-bar` under every tab, the help and the settings (one line: the account as a menu button `#account-toggle` like Outlook's profile menu – `#account-menu` opens above it with icon entries "Nextcloud öffnen" `#nextcloud-open` (NEXTCLOUD_URL from `/api/config` in the default browser, `openBrowserWindow`), "Einstellungen" `#settings-open`, "Hilfe" `#help-toggle` and "Verbindung trennen" `#disconnect` (two clicks like "Zurückziehen": `armDisconnect`), closes on Escape or a click elsewhere; its head `.account-menu-head` shows the whole name `#account-menu-name` and the storage `#account-storage` with a bar `#storage-meter` (used share of the quota, red from 90 %) – nothing else in the bar; fixed height `--bar-height`, the "Senden" footer sticks above it; variants are shown to the user before UI changes like this); one entry per link or confidential message: title = subject of its sent mail (`history.ts`, store `sent-mails`, Graph ID with `Prefer: IdType="ImmutableId"`; a click opens the mail via `openSentMail`: `GET /api/shares/:id/mail` translates the stored immutable ID into the current EWS ID with Graph `translateExchangeIds`, then `displayMessageFormAsync` – own mailbox only), below it plain text (file name, "Dateianforderung", "Vertrauliche Nachricht"), the kind as the symbol on the left (document, upload arrow, envelope with lock – no labels or coloured badges) (before sending: the draft's subject, sent with every link request as `subject`, `recordDraftSubject`; a subject typed later follows via `PATCH /api/jobs/:id` from the 4-second check `syncDraftSubject`; unsent without subject "(Noch kein Betreff)", older entries "(Betreff unbekannt)"), icon buttons Kopieren/Kennwort/Einfügen/Zurückziehen next to the title (messages: store `messages`, token `msg-<Send ID>`, only Kennwort and Zurückziehen – CloudShare never keeps their key) (long names shortened in the middle, extension kept – `nameParts`) (`ICONS` in `taskpane.ts`, also filled into the help via `data-icon`) and one meta line "period · password"; revoke via `DELETE /api/shares/:id`, `revokeShare` in `shares.ts`; links are created on insert, so links whose job has not been dispatched are marked `unsent` – a job that expires without ever being armed (draft discarded, `armedOnce: false`) gets its links revoked by the watcher via `onUnsentExpired`/`revokeUnsentLinks`); "Hilfe" in the account menu (`#help-toggle`, `showHelp`) shows the guide in place of the current tab – a user guide for everyday users, `<details>` sections with texts `help.*` in the language files (keep it in plain words and in step with the UI when features change). "Senden" starts with a switch (`kind` radios, `selectKind`/`renderKind` in `taskpane.ts`) between "Dateien" (attachments + drop zone), "Nachricht" ("Vertrauliche Nachricht" via `/api/messages` = a Vaultwarden text Send protected with the step password, never stored in Nextcloud) and "Anfordern" (upload link via `/api/requests`); only the chosen part is shown and the single footer button `#submit` names what it inserts (`renderSubmit`). Below: password, "Kennwort senden an" (`<select>`), and "Gültigkeit und Sprache" collapsed behind a one-line summary (`renderValidity`; it also holds "Sprache für die Empfänger" and names it in the summary). "Ohne Kennwort" is only offered for "Dateien" – prevent invalid choices in the UI rather than reporting them after the click. Read mode: the manifest also has a pinnable `MessageReadCommandSurface` button (plus legacy `ItemRead` form) opening `taskpane.html?view=read` (`readMode`, `startReadView`) – tabs "Nachricht" (`#tab-mail`/`#panel-mail`: the shares whose token (`/s/<token>`) appears in the read mail's body, `mailTokens`; selected again on `ItemChanged`, in place of "Senden") and "Verlauf" (all valid links, as when writing); no server-side mail↔share mapping, no new permissions. A manifest change needs a new `<Version>`. Links are inserted as an email-safe HTML card (`addin/src/taskpane/mailCard.ts`, tables + inline styles, no signature – the sender's signature goes into the password mail, see below).
- Personal settings ("Einstellungen" `#settings-open` in the account menu of the bottom bar, `#panel-settings` shown in place of the tab like the help – `showOverlay`): add-in `settings.ts` (form, `loadSettings`, `userSettings`), server `settings.ts` (store `settings`, `retention: false`, only changed fields; `settingsFor` = `config.userDefaults` from `DEFAULT_*` + stored + `availableSettings`), `/api/settings` GET/PUT/DELETE. Covers the offered password ways and the preselected one (`applyChannelChoices`, keeps the way a mail already uses), the notices (checked in `attachNoticeJob`, `runNotices`, `noteUndeliveredSms`; only where the server switch is on), the add-in language (`auto` or a code, also in `roamingSettings` `cloudshare-settings` → `preferredLanguage` in `i18n.ts`; reload once when it differs) and the signature of the password mails (`server/src/signature.ts`, `signatureHtml`: own text or else `MAIL_FOOTER`, plain text only – deliberately no formatted/HTML signature; empty line = paragraph (`signatureParagraphs`), profile placeholders via `fillTemplate`, escaped, each paragraph a `<p>` in `TEXT_STYLE` like "Guten Tag"; fixed in `PasswordJob.signature` when arming, built anew for "send again"). The link card carries no signature. SMS rules and server switches are never user settings. Keep the help section `help.settings.*` in step.
- Per-draft state lives in `item.sessionData` (`DraftState` in `shared/office.ts`: `jobId`, `password`, `noPassword`, `maxAccess`, `passwordTo` = other password recipient (job field, only that address gets the password mail), `separate` = one password and password mail per "Als Link einfügen" step (`step` ID per click, `PasswordJob.separate`), `lastStep` = ID and password of the last step with a password – after it "Gleiches Kennwort wie zuvor" (`#mode-same`) is preselected and the next click reuses that step (`stepForClick`, joins the part on the server: one password, one password mail/SMS for files, message and upload link), `links` = share tokens of inserted links; if none of them is left in the body, `releaseDraftIfLinksGone` drops job/password/tag – taskpane on focus and every 4 s while locked, send handler before arming; drafts without `links` are never released). All files of one mail share one password, one Vaultwarden Send and one password mail (or, with "Ohne Kennwort" – file links only, `noPassword: true` on `/complete` – no password, no Send; with `DOWNLOAD_NOTICE` a job without password (`PasswordJob.noPassword`, `noticeShares`) only waits for the sent mail to register the download confirmation; `DraftState.noPassword` + `jobId`). With "per SMS" the pane hides "Kennwort abrufbar"/"Kennwort-Link gültig für" and SMS steps get Sends with `SEND_MAX_EXPIRE_DAYS`; the backend appends to an existing job via `jobId` on `/complete` unless it was already dispatched. The password mail is sent only after the mail was really sent: the taskpane tags the draft with the Office.js custom property `cloudshareJob` (MAPI `cecp-<add-in ID>`, `ADDIN_ID` env must match the manifest `<Id>`), the send handler only arms the job (`/api/jobs/:id/arm`, stores a Graph token with Mail.Read(.Shared) + Mail.Send(.Shared); the handler passes a "From" that differs from the user so shared-mailbox "Sent Items" are searched too and the password mail uses the same sender), and `server/src/jobs.ts` polls "Sent Items" and then mails the actual recipients. Password channel per insertion (each link request carries `passwordTo`/`passwordSms`, `deliveryFrom`; a step collects the ways of its links in `SeparatePart.deliveries` and sends each once – `partDeliveries`, `sentWays`; older steps fall back to the job's one way set by `PATCH`/`/arm`): recipients, `passwordTo` or `passwordSms` (seven.io, `sms.ts`, after sending, password read from the Send, webhook `/webhooks/seven`, status in `deliveries.ts`; `SMS_ALLOWED_COUNTRIES` limits the countries by calling code (`countries.ts` reads ISO codes, calling codes, German/English names and groups), `SMS_ALLOWED_NUMBERS`/`SMS_BLOCKED_NUMBERS` are regular expressions on the E.164 number (default blocks 0800/0900/0180; landlines allowed) – `smsNumberProblem` in `sms.ts` and `taskpane.ts`, the pane refuses such numbers while they are entered, the server on `PATCH`/resend and before every SMS; a failed SMS never falls back to another channel – the sender gets a note without password, `smsProblemMailHtml`; a refused SMS right away with the armed token, one reported later as not delivered only with `SMS_NOTICE` (app token; unset it follows `DOWNLOAD_NOTICE`, `envFlag` in `config.ts`)). Sends have two dates: recipients' access ("Kennwort-Link gültig für") and deletion = link expiry, so links with password last at most 30 days (Vaultwarden limit, `passwordLinkMaxDays`); `passwordRefs.ts` stores only the Send ID per sent step so the owner can see and resend the password ("Kennwort" in "Verlauf", `/api/shares/:id/password[/send]`) until the links expire – CloudShare never stores passwords itself; optional `templates.json` (`templates.ts`, user → department → default) and download confirmation (`notices.ts`, app permission `Mail.Send`, `DOWNLOAD_NOTICE`) and upload notification (same module, `UPLOAD_NOTICE`: upload links are `StepShare.request` with `knownFiles`, registered as `kind: "upload"`, each pass mails the new files of the folder until the link expires); every mail CloudShare sends itself (password mail, download confirmation, SMS notes) uses `mailLayout.ts` – text, one card with an accent per kind (blue password, green downloaded, red problem), the line `mail.automatic`; keep new mails in that layout. All persistent state (jobs, password entries, deliveries, notices, the cleanup list of uploaded files – `cleanup.ts`, `CLEANUP_AFTER_DAYS`, deletes upload folders after link expiry – and the Nextcloud connections) lives in one SQLite database `/data/cloudshare.db` (`db.ts`, Node 24 built-in `node:sqlite`): one table `entries (store, key, data)`, every row sealed AES-GCM with `CREDENTIAL_KEY` (`storage.ts`); each module keeps a `PersistentMap` in memory – `set`/`delete` write their row, an entry changed in place needs `map.save(key)`; a daily pass deletes rows not written for `DATA_RETENTION_DAYS` (default 365, `startRetention`), except maps created with `retention: false` (connections, cleanup list). No upload size cap except the user's Nextcloud quota (checked up front via OCS `cloud/user`, 507 → `NEXTCLOUD_QUOTA_EXCEEDED`).
- "Zustellnachweis" (delivery proof, `DELIVERY_PROOF`, follows `DOWNLOAD_NOTICE` when unset; `docs/architecture.md` 2.12): a checkbox `#proof` in "Gültigkeit und Sprache", never ticked by default, offered only with the server switch; link requests carry `proof`, `proofId` (`DraftState.proofId`), `client` (`proofRequest`). `server/src/proof.ts` (store `proofs`, `retention: false`, kept `PROOF_RETENTION_DAYS`, default 1095): one case per mail with a tracking ID (`newTrackingId`, "20261117-1146-7Q2F"), events hash-chained (`addEvent`, `verifyCase`) – link created (SHA-256 computed while the chunks pass, `UploadState.hash`), mail sent with Internet Message-ID and To/Cc/Bcc (`recordMailSent` in the job watcher), password sent / SMS status (`deliveries.ts`), password link and messages opened (Send access count), every download (`publicDownloadTimes`), files received, link revoked/expired (`endLink`) – `proofWatcher.ts` every 10 minutes. File and upload links of a case go into the mail as the gateway `/r/s/<token>` (`proofGateway.ts`: the recipient enters an address the mail went to, gets a six-digit code from the sender's mailbox via the app token, confirms it – address, IP, browser recorded, signed cookie per link, 303 to Nextcloud; plain HTML forms, own CSP); messages have no gateway. PDF via `pdf.ts` (own minimal writer, no dependency) and `proofPdf.ts`, opened by "Nachweis" in "Verlauf" through a signed 5-minute address (`/api/proofs/:id/link`, `/proof/:id.pdf`, `sign`/`signedBy` in `storage.ts`). Card, password mail and download confirmation name the tracking ID.
- Placeholders `%%PUBLIC_BASE_URL%%`, `%%PUBLIC_HOST%%`, `%%ENTRA_CLIENT_ID%%` in add-in files and manifest are replaced by `docker/entrypoint.sh` at container start (copied from `/app/public.tpl` to `/app/public`), so one image works for any environment. Then `server/src/index.ts` runs `localizePublic` (`i18n.ts`): the string marker `"%%CLOUDSHARE_I18N%%"` in the JS bundles becomes the `addin` texts of every language as JSON (`{ fallback, languages }`), `%%t:…%%`/`%%LANG%%`/`%%LOCALE%%` in HTML the texts of `LANGUAGE` plus a copy `taskpane.<language>.html` per language (the taskpane entry `main.ts` swaps in the client's page via `language.ts` before it imports `taskpane.ts`), in the manifest English `DefaultValue`s with one `Override` per other language (English as fallback for missing texts, own files/overrides from `/config/locales`, mounted from `env/config/` together with `templates.json`). Comments in these files must not contain `%%` (the smoke test fails on leftovers). UI tests and manifest validation localize via `addin/scripts/localize.mjs`; add-in unit tests load `locales/de.json` in `addin/test/setup.ts`. The backend also serves `/manifest.xml` for the M365 admin center.
- Keep `docker/entrypoint.sh` LF-only (enforced by `.gitattributes`).
