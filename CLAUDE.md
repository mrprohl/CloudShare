# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

CloudShare – Outlook add-in for classic and new Outlook on Exchange Online: large files are uploaded to the sender's own Nextcloud account and inserted as a password-protected public link; the password is delivered to the same recipients in a second, automatically sent mail as a Vaultwarden Send. Full architecture, setup (Nextcloud user_oidc, Vaultwarden) and known risks: `docs/architecture.md`; Microsoft 365 step by step (Entra app registration, add-in deployment, Exchange, error table): `docs/microsoft-365.md`; operations manual: `README.md`. Conventions: everything in the repository is English – identifiers, code comments, file names, documentation, logs and admin-facing script output. Text seen by end users and mail recipients (taskpane UI, Outlook notifications/Smart Alert texts, manifest labels, link cards, password mail, SMS/templates defaults, `HttpError` messages shown in the add-in) is never written inline: it lives in the language files `locales/<language>.json` (`de`, `en`): the add-in follows the Outlook display language (`Office.context.displayLanguage`, English if there is no file – `pickLanguage`), sends it as header `X-CloudShare-Language` so `server.*` error texts come in it (`AsyncLocalStorage`, `withRequestLanguage`), what recipients get – link card, password mail, SMS – comes in the language of the personal setting `recipientLanguage` ("Sprache für die Empfänger" under "Weitere Einstellungen" – the only place to choose it, no choice per mail in "Senden"; `recipientLanguage()` in `taskpane.ts`; card via `inLanguage`, server per step `SeparatePart.language` + `inRecipientLanguage`), while notes to the sender (download/upload confirmation, SMS notes) come in the language of their add-in when they pressed "Send" (`ArmedSend.language` → `Notice.language`, `PasswordRef.senderLanguage`, `inSenderLanguage`), `templates.json` may hold texts per language per level (`"languages"`, `mailLanguage`), the manifest gets Overrides for each language's `_meta.locale` and `_meta.regions` (`manifestLocales`), and env `LANGUAGE` (default `en`) is the preselection and fallback – add-in code uses `t("key")` from `addin/src/shared/i18n.ts` (section `addin`), the server `t("section.key")` from `server/src/i18n.ts`, `taskpane.html`/`manifest.xml` use `%%t:section.key%%`. Every new key goes into every language file with the same placeholders (`server/test/i18n.test.ts` enforces it, plural forms `_one`/`_other`). Keep the German wording Outlook-like ("Nachricht", "Kennwort").

## Architecture

One container serves everything behind Caddy:
- `server/` – Fastify backend (ESM, TypeScript). Validates the Office SSO token (`auth.ts`, audience `api://<host>/<client-id>`, scope `access_as_user`) and uses MSAL On-Behalf-Of only for Graph (`Mail.Send`).
- Nextcloud does not accept Entra tokens (typically it logs in via another IdP, e.g. Keycloak through `user_oidc`). Instead each user connects once via Nextcloud Login Flow v2; the resulting app password is stored encrypted per Entra `oid` in the database (`credentials.ts`, store `credentials`, key `CREDENTIAL_KEY`) and used as Basic auth. A 401 from Nextcloud deletes the stored credential and returns error code `NEXTCLOUD_NOT_CONNECTED`, which makes the taskpane show the connect view.
- Nextcloud access is server-to-server (no CORS on Nextcloud): WebDAV chunked upload v2 + OCS share API (`nextcloud.ts`). Nextcloud-reported URLs are rewritten onto `NEXTCLOUD_URL`. Vaultwarden Sends are created through `bw serve` running in the same container on 127.0.0.1:8087 with a service account (`vaultwarden.ts`). Upload/job/pending-login state is in-memory (`store.ts`) → single instance only.
- `addin/` – XML manifest + taskpane (Nextcloud connect/disconnect, converts existing attachments via `getAttachmentContentAsync` → upload → `removeAttachmentAsync`, plus file picker (`window.showOpenFilePicker` first, hidden `<input type="file">` as fallback – classic Outlook's WebView did not reliably open the dialog for a file input; steps are traced with `CLIENT_TRACE`) and drag & drop onto the "Senden" tab for files beyond Outlook's limit – in classic Outlook the WebView2 file dialog sometimes opens behind the Outlook window; inserts links) + event handlers in `commands.ts`: `OnMessageAttachmentsChanged` shows an InsightMessage with a "open taskpane" action (add-ins cannot open the taskpane themselves), `OnMessageRecipientsChanged` runs the same check (the size is the total of all attachments of the mail, and it depends on the recipients: `ATTACHMENT_THRESHOLD_MB` as soon as one is outside `INTERNAL_DOMAINS` – default the user's own domain –, else `ATTACHMENT_THRESHOLD_INTERNAL_MB` and `ATTACHMENT_POLICY_INTERNAL`, also without recipients; `attachmentRule` in `shared/office.ts`, 0 = every attachment, texts without a size; in the pane every attachment is ticked whatever its size, an unticked one stays unticked on redraw; every file row has an "×" that removes the file – no "Groß" mark), `OnMessageSend` runs with manifest `SendMode="SoftBlock"`; env `ATTACHMENT_POLICY` (served via `/api/config`, cached in `roamingSettings`) decides: `enforce` blocks large attachments before arming the password mail (no "Send anyway"), `suggest` arms the password mail first and relaxes to PromptUser via `sendModeOverride` (Mailbox 1.14). The taskpane mimics Outlook (Fluent 2 tokens, Office theme, Outlook wording "Nachricht"/"Kennwort") – keep new UI consistent with that. A description (`.hint`) under an item – option, switch, field, select – sits as close as the line under "Gültigkeit" everywhere (5–6px in the rendered pane from the item's bottom – letters or edge – to the top of the description's letters), and so does the text right under a section heading ("Anhänge", "Vertrauliche Nachricht", "Dateien von Empfängern erhalten"; `.section-text`, `#no-attachments`; settings headings: `legend + .settings-text`) and the description under a checkbox (`.checkbox-hint`, settings); the margins differ by item (comment in `taskpane.css`) – check new hints against it, and remember that a hidden element is still a CSS neighbour (use `:not([hidden])`). While something loads – the start of the pane (`#start-view` in `taskpane.html`), "Verlauf", "Zustellnachweise", the links of a mail being read, settings not loaded yet – grey shimmering placeholders in the shape of the content show (`skeleton.ts`: `skeletonRows`, `skeletonForm`; role status, "Wird geladen …" for screen readers, no shimmer with reduced motion); a reload keeps the list in sight, a failure removes them. The message bar stays in sight at the top while the pane scrolls (`position: sticky`). Messages run down (`SUCCESS_MESSAGE_SECONDS`, default 5: a ring around the tick, "!" or "i" empties clockwise, paused on hover/focus, `setStatus`); progress (kind `progress`) and messages with "Erneut versuchen" stay. Bundled as IIFE because classic Outlook runs the handlers in a JavaScript-only runtime (no DOM, no ES modules); `commands.js` is built with target `es2016` and without `Headers`/`Promise.finally` (guarded by `addin/test/bundle.test.ts`); it registers its handlers immediately (classic) and again in `Office.onReady` (browser runtime: office.js loads `Office.actions` only after the script ran – `commands-load.test.ts`), and that runtime only allows SSO and fetch because the server serves `/.well-known/microsoft-officeaddins-allowed.json` listing `commands.js`.

- "Zustellnachweis" (delivery proof – never mixed with links without one in a mail: `assertNoProofMix`/`PROOF_MIX` on insert and `/arm`, `DraftState.proofMail` + `applyProofLock` in the pane – no note box and no "i": when the switch is fixed, the reason is appended to its hint `#proof-hint`; `DELIVERY_PROOF`, follows `DOWNLOAD_NOTICE` when unset; `docs/architecture.md` 2.12): a switch `#proof` below the password, never on by default, offered only with the server switch and only for "Dateien"; link requests carry `proof`, `proofId` (`DraftState.proofId`), `client` (`proofRequest`). `server/src/proof.ts` (store `proofs`, `retention: false`, kept `PROOF_RETENTION_MONTHS`, default 36): one case per mail with a tracking ID (`newTrackingId`, "20261117-1146-7Q2F"), events hash-chained (`addEvent`, `verifyCase`) – link created (SHA-256 computed while the chunks pass, `UploadState.hash`), mail sent with Internet Message-ID and To/Cc/Bcc (`recordMailSent` in the job watcher), password sent / SMS status (`deliveries.ts`), password link and messages opened (Send access count), every download (`publicDownloadTimes`), files received, link revoked/expired (`endLink`) – `proofWatcher.ts` every 10 minutes.
